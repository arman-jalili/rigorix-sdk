# Code of conduct

## The short version

Be the colleague you would want on a review: assume competence, argue about the
work rather than the person, and make it easy for someone to be wrong without
being humiliated. This project's subject matter is auditability, so a discussion
that cannot be followed by a newcomer is a defect, not a style.

## Expected

- **Critique the artifact.** "This refusal names neither digest" is a review; "you
  clearly don't understand the protocol" is not.
- **Show the evidence.** This repository's rule is that a claim comes with the
  command that produced it. Apply it to review comments too.
- **Leave room to be wrong.** The history of this repository includes a filing
  whose premise was inverted by the code; the correction was accepted and
  recorded. That is the norm, not an embarrassment.

## Not acceptable

- Harassment, intimidation, or discrimination of any kind, in any channel.
- Sexualised language or imagery, or unwelcome attention.
- Publishing someone's private information without permission.
- Sustained disruption: repeating a rejected argument, derailing threads, or
  reopening a decision without new evidence.
- Retaliation against someone who reports a problem.

## Scope

This applies in every project space — issues, pull requests, reviews, commit
messages, and any channel where you are representing the project.

## Reporting and enforcement

Report a conduct problem privately to the maintainers via a **private GitHub
security advisory** on this repository (`Security → Report a vulnerability`),
which is monitored; use the subject line "conduct". Reports are read by the
maintainer on call and kept confidential from everyone else.

Responses are proportionate: a private clarification, an edited comment, a
warning, or removal from the project's spaces. The maintainer recuses from any
report in which they are involved.

Security vulnerabilities are a different channel: see [SECURITY.md](SECURITY.md).
